# 当前进行中目标

更新时间：2026-08-01

本文件是本项目当前唯一执行基线。后续旧方案、旧截图和旧文档若与本文件冲突，以本文件为准。

## 最终目标

在不改变 Codex 原生信息架构、文本内容和交互热区的前提下，实现一套与《黑神话：悟空》深度融合的 Codex 视觉主题；除用户已明确授权的主输入器外框高度与轮廓外，其余组件尺寸继续服从本机原生实现：

- 保持 Codex 原生页面结构，不增加额外侧边栏、底栏、主题控制栏或开关按钮。
- 正式包放入约定位置即可使用，并随 Codex 启动和退出；移除主题包后完整回归原生。
- 主题不得修改 `ChatGPT.exe`、`app.asar` 或官方配置，不得以长期 PowerShell 启动脚本作为最终方案。
- 关闭或移除主题后不得残留背景、标记、宠物、监听端口、watcher 或调试进程。
- 所有实现优先保证稳定与最小资源占用，不能以视觉效果换取崩溃风险。
- 所有未获用户单独授权的宽高、间距、内边距、位置、响应式断点和命中区以本机已安装 `ChatGPT.exe` 的 `app.asar` UI 源码为几何真值；主输入器外框按最终审稿图使用受限高度卷页比例，但其原生文字、状态、按钮尺寸、可访问语义和交互能力不变。

## 当前实施顺序

### 1. 资源与稳定性硬门槛

这是当前第一阻断项，完成前不叠加宠物或复杂动效。

- 背景按需加载，不允许启动时预载全部场景。
- 稳态仅允许一张背景驻留；过渡期间最多两张。
- 单张背景、图库总量、双图过渡和 UI 材质必须同时受“压缩字节 + 解码像素”硬预算约束；不能让高压缩率超大图绕过内存门禁。
- 不使用永久全屏 `will-change`、全屏滤镜或无必要的缩放合成层。
- 不做跨模式或相邻场景预取。
- 每次调试前后、每个长阶段至少每 30 分钟、任务收尾前检查一次进程、端口和内存。
- 只关闭本项目明确创建的调试实例、watcher、测试进程和工具进程；保留 Codex 主界面、renderer、GPU 与 app-server。
- 常态不保留主题调试窗口；实机截图与资源采样完成后立即关闭，并验证其 watcher、子进程和专用端口全部释放。

### 2. 背景与新建任务页

- 新建任务页使用战斗背景池；进入已有对话后切换为风景背景池。
- 两个背景池分别轮换，切换时使用低成本交叉淡化。
- 背景必须完整覆盖整个 Codex 窗口，不能只覆盖侧边栏或中央局部。
- 战斗视觉以杨戬与大圣为主；用户最新否决的候选大圣图与原夜叉王裂焰图均退出活动图库和运行包，源文件只作保留证据。
- 夜叉套、神锋、金箍棒等元素必须来源准确，不使用失真的手绘替代。
- 风景模式使用用户认可的纯画面、场景与建筑素材，不采用普通战绩图或杂乱战斗截图。
- 杨戬主背景使用用户指定的白底水墨对决图。
- 当前活动图库为 9 张：2 张主战斗、2 张次级战斗、5 张风景；默认回退图为 1920×1080 的 `great-sage-staff.jpg`，不再回退到低分辨率 `great-sage-return.jpg`。
- 新建任务页原生标题和 56×56 图案允许替换，但必须保留原生占位、尺寸与布局；当前文案“此去，欲破何局？”与真实金箍棒模型缩略图属于待实机审计版本，不视为最终验收。

### 3. 输入框

- 用户上传的三张最终参考图已取代 V1–V9 候选，允许直接实现并测试；主输入器、上下文条、进行中目标条、计划/变更摘要和项目上下文条统一使用第一张参考图的纸面底纹。
- 纸面综合色阶以用户最新暗色参考为准：当前 V17 材质重建目标为 `RGB(135,117,93)`，四类活动产物内区中位色约 `RGB(134–135,117,93–94)`；主输入器、上下文/目标条、计划/变更条和项目上下文条必须从同一源重建并使用同一暖灰黄赭 matte，不能分别套滤镜或出现亮黄断层。
- 主输入器不再完全套用原生高度或圆角外框：宽度与底部锚点仍由原生布局负责，外框使用 `184:25` 的短卷页比例，并限制在 `96–120px` 高度内；用户最新原生截图中最大宽度 surface 约为 `736×100px`，主题必须在该宽度落到约 `100px`，不得回退为 120px 的偏高版本、审稿概念图中的高大输入区，也不得写死某一窗口截图的绝对宽度。
- 外形使用轻量切角卷页轮廓与静态纸面，不沿用原生圆角矩形，也不使用会把纸面中央挖空的 alpha 位图遮罩。
- 原生编辑器、footer、上下文条、排队/目标条、项目条、按钮尺寸、文字、ARIA、动态状态和命中区继续保留；只允许编辑器外壳与 footer 在卷页内获得与参考图相符的安全内边距。排队消息与进行中目标继续使用贴在主卷页上方的官方 stack，并按当前安装包解包得到的真实两层拓扑绘制：一个外层 queue panel 包含 N 个 internal queue item，随后是一个外层 goal panel；只有整组首个外层面板拥有左上/右上外部切角，每条内部消息在组内拥有独立纸纹与原生 1px 接缝，后续目标面板以直边连续承接。不得把每条消息提升为独立外层卡片，也不得把一张纸面按总高度拉长；独立计划/变更进度 pill 才保留完整圆角。
- 不修改用户提示词、占位文案或回答内容；助手回答保持无额外外框。
- 纸面、角纹、云纹、边线、墨色和控件状态按用户最终参考高保真实现；不得退化为泛古风金框、换色皮肤或拉伸位图。
- V1–V9 全部作为失败/历史候选保留，不再参与当前实现决策。

### 4. 侧边栏、顶部入口与应用菜单

- 一级条目用于项目条和无项目对话，采用黑神话“游记”目录的深墨条材质；二级条目用于项目下对话，采用目录正文行与浅纸选中带。
- 必须完整定义默认、悬停、焦点、选中、展开、禁用和未读/进行中状态的对应关系，不能只做静态截图。
- “新建任务 / 拉取请求 / 站点 / 已安排 / 插件”等顶部原生入口与“文件 / 编辑 / 视图 / 帮助”四个应用菜单同样替换材质，但仍由原生 DOM、文字、图标、热区和几何负责。
- 用户明确取消葫芦融入方案；活动 runtime、发布清单和后续设计均不得新增葫芦。

### 5. 新建任务页图案

- 保留官方 56×56 图标槽位、原始节点和命中关系。
- 卡通化短棍图案已被否决；当前候选直接从真实金箍棒模型参考生成 112×112 透明 WebP，在官方 56×56 槽位约占 50×42 px，显示深红棍身、兽纹端箍和旧金属层次，不增加背景徽章、墨尾贴纸或动画。alpha 安全边距、居中、倾角、可见面积、体积和原生几何门禁已通过，仍待用户实机验收。
- 当前题字“此去，欲破何局？”仍处于多轮验收中，不因技术测试通过而自动视为视觉通过。

### 6. Hatch Pet 宠物

两个宠物均使用 Hatch Pet v2 规范制作、修复、验证和打包。

- 名称固定为“小天命人”和“小八戒”。
- 小天命人使用高保真夜叉套与正确神锋；右脚夜叉护甲、武器前后完整性必须修复。
- 小天命人的跑动与棍花动作参考游戏动作；现有录屏只可用于背面跑动和棍花节奏，不推断不存在的正面细节。
- 小八戒保持正确九齿钉耙，外观参考游戏小八戒与 InArt 1/12 手办，整体更可爱但不失真。
- 小八戒悬停动作改为单手持钉耙、另一手捧腹大笑，动作节奏参考“奶龙捧腹大笑”，不直接复制角色造型。
- 宠物动作不得因悬停发生比例突变、装备变形、方向错误或不自然位移。

### 7. 最终随 Codex 启停

仅在背景、输入框和宠物全部完成并通过实机审查后集中处理。

- 优先寻找与 Codex 宿主生命周期绑定的原生或轻量宿主方案。
- 不把 PowerShell 常驻 watcher、启动快捷方式或手动重启作为正式交付。
- 保持“安装即用、移除即回原生”的用户体验。

## 不可违反的约束

- 不删除、移动或覆盖用户本地任何原始文件；只允许在项目或明确的主题安装目录中新增和修改本项目文件。
- 不使用 Computer Use 审查 Codex；以只读方式审计 `ChatGPT.exe` 所在应用包的 UI 源文件。
- 常态只保留当前 Codex 控制窗口；实机审查时最多临时增加一个主题调试窗口，截图与采样后立即关闭。
- 不新增表情符号装饰。
- 不改变 Codex 原生侧边栏宽度、输入框长度、环境信息窗口尺寸、按钮热区和回答排版；主输入器外框高度与轮廓仅按本文件第 3 节的显式例外调整。
- 每轮只运行与变更相关的定向测试；里程碑或推送前再运行必要的契约测试。
- 每轮维护需求、设计、分工与工作日志，并对本轮精确暂存、提交和推送；不得混入用户已有或无关改动。
- 高难度模块拆成可独立回退的小里程碑；每个里程碑通过针对性测试后立即精确 commit/push，不允许把多个验收轮次堆在一个大提交里。
